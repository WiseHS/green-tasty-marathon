# Green & Tasty — EPAM IT Marathon

Навчальний проєкт ресторанного застосунку на основі вихідних матеріалів EPAM IT Marathon 6.0.

## Поточний стан

Застосунок розгорнуто на безкоштовних сервісах Render із PostgreSQL на Neon.

- Сайт: https://green-tasty-marathon.onrender.com
- API readiness: https://green-tasty-api.onrender.com/health/ready
- Код розгортання: гілка `feature/render-neon`.

Додаткова конкурсна функціональність версії **1.3.0** — [побажання гостей до страв](docs/DISH-REQUESTS.md): збереження в кошику гостя, перегляд та сводка Owner, передавання призначеному офіціанту. Коментарі різних гостей не губляться при об'єднанні однакових страв; відправлені побажання фіксуються у snapshot. Безкоштовний backend засинає після бездіяльності, тому перше відкриття може тривати довше.

Версія 1.2.0 завершує базовий груповий сценарій: у Reservations натисніть **Group order**, перевірте страви й статус кожного гостя та надішліть спільне замовлення. Чернетки гостей не включаються. Офіціант бачить об'єднані позиції, суму та розподіл за учасниками. Це завершення вихідного ДЗ, а не окрема конкурсна функція.

- `frontend/restaurant-frontend-app` — Angular інтерфейс.
- `backend/Restaurant.Web` — ASP.NET Core HTTP сервер, PostgreSQL, локальна авторизація та зберігання зображень.
- `backend/restaurant-backend-app` — .NET 10, AWS Lambda та DynamoDB.
- `infra/terraform` — початкова AWS інфраструктура.
- `aqa/restaurant-aqa-framework` — автоматизовані тести.
- `aqa/group-order-e2e` — Playwright: 23 сценарії ДЗ та 7 сценаріїв додаткової функції, GitHub Actions зі звітами та скриншотами.

Початкові матеріали та авторські позначення EPAM збережені. Наявний навчальний код не видається за власну додаткову функціональність.

## Перевірка

- Backend: **147 тестів пройдено**, Release publish успішний.
- API на Release збірці з Neon: **33 перевірки пройдено** — реєстрація, вхід, бронювання, одночасні запити, pre-order, гостьова сесія, зображення та розмежування доступу.
- Frontend: обидві перевірки TypeScript і production build успішні.
- Загальний frontend набір версії 1.3.0: **223 пройдено, 46 помилок**. Список 46 невдалих тестів збігається з попереднім прогоном; нових невдалих тестів не додано. Окремо перевірено нові компоненти, HTTP-контракт і збереження побажань.
- У браузері перевірено реєстрацію, вхід і відображення меню та ресторану з Neon.

На публічному Render API також пройдено **33 перевірки**. Підтверджено CORS для адреси сайту, POST preflight та відкриття внутрішніх Angular маршрутів. У браузері публічного сайту перевірено меню, ресторан і вхід; реєстрацію та авторизацію також підтвердив користувач. [Запуск, розгортання та обмеження](docs/RENDER-NEON.md).

Версія 1.2.0 опублікована на обох сервісах. Груповий сценарій: **58 API-перевірок** на тестовій гілці Neon; на публічному сайті перевірено вхід, перехід із Reservations, перегляд учасників і відправлення спільного замовлення через інтерфейс. **11 додаткових публічних API-перевірок** підтвердили збереження замовлення, доступ офіціанта, кількість порцій, блокування та повторну відправку.

## Розгортання

Для нового варіанта використовуйте [Render + Neon](docs/RENDER-NEON.md). Початкова [AWS інструкція](docs/ORIGINAL-AWS-DEPLOYMENT.md) збережена для довідки. Наявні AWS адреси й ідентифікатори у старих конфігураціях належать навчальному прикладу; переносний сервер їх не використовує як живі ресурси.

Оригінальні GitHub Actions збережені в `docs/original-workflows` як `.reference` файли: вони не запускаються автоматично. Render конфігурація збережена у `render.yaml`; поточні сервіси створені через dashboard із Public Git Repository і потребують ручного запуску наступних деплоїв.

Секрети, локальні залежності та результати збірки не повинні зберігатися у Git.
